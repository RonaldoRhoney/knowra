KNOWRA — Foundation 0.1

Antes de escrever código, quero que o Claude Code compreenda uma coisa:

KNOWRA não é um chatbot com gamificação.

É uma:

Plataforma de conhecimento interativo orientada por IA, na qual a curiosidade do usuário se transforma em aprendizado, desafios e progressão.

O núcleo é:

PERGUNTAR → APRENDER → DESAFIAR → DEMONSTRAR → EVOLUIR

Esse será o coração do produto.

4. O grande cuidado: XP

Aqui quero que o Claude pense como um game designer + engenheiro.

Não podemos criar:

pergunta = XP.

Isso quebraria o sistema.

O modelo inicial deve considerar:

XP =
dificuldade
× qualidade da resposta
× conhecimento demonstrado
× bônus contextual

Exemplo:

Pergunta fácil

25 XP base.

Usuário demonstra 90% de domínio:

22,5 XP

Bônus de sequência:

+10%

Total:

24,75 XP → 25 XP

Posteriormente podemos sofisticar esse cálculo.

5. Áreas de conhecimento

Não devemos criar uma lista rígida demais.

A arquitetura precisa permitir:

Área
 └── Subárea
      └── Tópico
           └── Conceitos

Por exemplo:

Tecnologia
 └── Programação
      └── Python
           ├── Variáveis
           ├── Funções
           ├── Classes
           └── APIs

Isso será fundamental para o futuro Knowledge Map.

11. Regra de ouro para o Claude

Eu colocaria isso literalmente na documentação:

Antes de implementar uma funcionalidade, entenda o problema que ela resolve.

Antes de escolher uma tecnologia, avalie suas consequências.

Antes de alterar uma arquitetura existente, verifique dependências e impactos.

Não implemente funcionalidades apenas porque parecem interessantes.

Se identificar uma solução melhor que a especificada, apresente a proposta, explique o motivo e preserve o objetivo original do produto.

Isso transforma o Claude de "gerador de código" em engenheiro responsável pelo sistema.
